## 小安的一天（回放）

**09:00**　小安打開 Claude Code，模型是 Opus。他打了一句：

> 「幫我看懂付款模組，找出為什麼發票金額偶爾會少一塊。」

**09:02**　Claude 開始探索。讀 `package.json`、讀目錄、讀 `src/payment/` 下面的檔案……一檔、兩檔、十檔。

**09:25**　它讀了 23 個檔案，其中 9 個跟發票完全無關（有一個是 email 範本）。

**09:40**　找到可疑的四捨五入邏輯。Claude 跑了一次測試，終端機吐出 1,800 行輸出，只有最後 12 行是失敗訊息。全部進了對話。

**10:30**　小安被叫去開週會。

**11:20**　回來，打了一句「繼續」。

**11:50**　改好、再跑一次測試，又是 1,800 行。

**13:10**　額度用完。bug 修到一半。

小安很困惑：「我才問了不到十句話啊。」

## 錢漏在哪裡？

用 [[token-01-amnesiac-consultant|第一篇]]的原理回頭看，三個漏洞清清楚楚：

> [!failure] 漏洞一：讀錯檔，每一檔都是一輪
> 「幫我看懂」是一個開放式指令，Claude 只能大範圍掃描。**每讀一檔就是一次工具呼叫，也就是一輪完整重送**，而且讀過的內容永久留在歷史裡。那 9 個無關檔案，之後的每一輪都還在付錢。

> [!failure] 漏洞二：測試輸出全進主對話
> 1,800 行裡真正有用的只有 12 行，但另外 1,788 行從此每輪都要重念。跑兩次就是兩倍。

> [!failure] 漏洞三：開會 50 分鐘，快取早就過期
> 回來那句「繼續」，整段已經很長的歷史以 1.25 的價格重寫，而不是以 0.1 的價格讀取。

小安只說了不到十句話，但 Claude 背後跑了七、八十輪，而且越後面的每一輪越貴。

## 同一個任務，換個做法

### 第 0 步：開工前就把「固定前綴」變小

這一步每個 repo 只要做一次，之後每個 session 都受益。

**精簡 CLAUDE.md。** 只放每次都需要的東西：套件管理工具、test/build 指令、目錄結構、架構限制、命名規範。判斷標準只有一個：

> **拿掉這一行，Claude 會出錯嗎？** 不會的話，就移到 skill 或 docs。

> [!warning] `@path` import 不會省 context
> 在 CLAUDE.md 裡用 `@docs/xxx.md` 引入的檔案，會跟著一起載入。它是整理方式，不是瘦身方式。

**加一段壓縮指示**，讓之後的 `/compact` 有固定規則可循：

```markdown
# Compact instructions
壓縮時務必保留：
- 修改過的檔案路徑與原因
- 錯誤碼與失敗的測試名稱
- 已做的決策（例如：這次不改 DB schema）
- 尚未完成的下一步
```

**維護一份 `docs/repo_map.md`**：入口檔、主要模組、各模組負責什麼。十幾行就夠，它能讓 Claude 不用自己去找。

**關掉這個任務用不到的 MCP server。** 每一個掛著的 MCP，它的工具定義每輪都在。

### 第 1 步：指名檔案，先規劃再動手

同樣的需求，小安改成這樣問：

```text
發票金額偶爾少 1 元。相關檔案應該是
@src/billing/invoice.ts 和 @src/billing/rounding.ts。
先不要改程式，給我你的假設和驗證計畫。
```

- **指名檔案**：少掉二十輪探索，也少掉二十份不相關的工具結果。
- **先 Plan**：方向錯誤的大範圍掃描是最浪費的；先確認假設，再讓它動手。

### 第 2 步：雜訊工作交給 subagent

跑測試、翻 log、查文件、分析影響範圍，這些工作的特徵是：**過程很吵，結論很短。**

```text
用 subagent 跑 billing 相關的測試，只回報失敗的測試名稱、
錯誤訊息和你判斷的原因，不要貼完整輸出。
```

subagent 有自己獨立的 context，那 1,800 行留在它那邊，主對話只收到一段摘要。

![[token-02-subagent.svg]]

再進一步，可以用 hook 預先過濾測試輸出（只保留失敗的部分），讓雜訊根本不進入任何 context。

### 第 3 步：模型分工

| 工作 | 建議模型 |
|---|---|
| 規劃、找難解的 bug、架構決策 | Opus |
| 照計畫實作、寫測試、重構 | Sonnet（用 `/model` 切換） |
| subagent 的雜訊工作 | Haiku（可設 `CLAUDE_CODE_SUBAGENT_MODEL=haiku`） |

同樣的 token，較小的模型占用的額度較少。**Opus 想、Sonnet 做、Haiku 跑腿。**

### 第 4 步：管理對話長度

這裡有三個工具，用在不同時機：

| 時機 | 工具 | 效果 |
|---|---|---|
| 任務做到一半，歷史已經很長 | `/compact 保留：檔案路徑、錯誤碼、這次不改 schema` | 把歷史壓成摘要，繼續同一個任務 |
| 任務完成，要換下一個 | `/clear` | 歷史歸零 |
| 任務很長，或要離開一段時間 | **交接檔** | 見下方 |

**交接檔**是小安後來最常用的一招。要去開會之前，他會說：

```text
把目前進度寫進 .claude/session-handoff.md，包含：
目標、改過的檔案、做過的決策、失敗中的測試、下一步。
```

然後 `/clear`。開完會回來，第一句話是：

```text
讀 .claude/session-handoff.md，繼續。
```

原本要用 1.25 倍重寫的一大段歷史，換成一份兩百字的交接檔。

> [!warning] 別在 session 中途改 CLAUDE.md 或開關 MCP
> 這些都在前綴的最前面，一動，後面整段快取全部失效。要調整，就在 `/clear` 之後做。

### 第 5 步：每天看一次 `/usage`

每天開工先跑一次 `/usage`，看看最大的占比來自哪裡：是某個 MCP？某個 skill？還是 subagent？**先找到最大的漏洞，再決定要補哪一個。**

## 改完之後

同一個發票 bug，小安第二次的流程是：指名兩個檔案 → Opus 給出假設 → subagent 跑測試回報 3 行結論 → 切 Sonnet 實作 → 開會前寫交接檔 → 回來 `/clear` 讀交接檔 → 完成。

十一點前修好，額度還剩一大半。

## 速查表：技巧與原理

| 技巧 | 對應原理 |
|---|---|
| `/clear`、交接檔 | 縮短歷史，打斷 N² 成長 |
| 精簡 CLAUDE.md、關 MCP | 縮小每輪都要付的固定前綴 F |
| 指名檔案、repo map | 減少工具呼叫輪數，也減少工具結果體積 |
| subagent | 雜訊留在另一個 context，主對話只收摘要 |
| Sonnet／Haiku 分工 | 同樣 token，較小模型占額度少 |
| 不在中途改 CLAUDE.md／MCP | 前綴變動會讓快取失效 |

> [!tip] 一句話記住
> **給它地圖，不要叫它自己找路；吵的工作派人去做，只聽結論。**
