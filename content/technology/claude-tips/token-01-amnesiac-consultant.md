## 一位很貴的顧問

想像公司請來一位天才顧問。他什麼都懂：程式、設計、法規、財務，問什麼答什麼。

但他有一個怪病：**每次你開口，他都完全不記得你們剛剛聊過什麼。**

所以他身邊跟著一位助理。你每問一個問題，助理就得把整本會議記錄從第一頁開始念給他聽：公司簡介、顧問守則、工具使用說明、你們從早上到現在的所有對話，最後才是你剛剛的新問題。顧問聽完整本，回答你一句，然後再次忘光。

第一次問，助理念 1 頁。第二十次問，助理念 20 頁。第四十次問，助理念 40 頁。

**你付的錢，是按助理念了幾頁來算的。**

這不是比喻過頭，Claude 真的就是這樣運作的。這一篇用這位顧問，把整個系列會用到的五條原理一次講完。

---

## 原理一：每一輪都要重念整本記錄

語言模型本身是**無狀態**的，它不會「記得」上一輪。你看到的「連續對話」，其實是每一輪都把下面這些東西**全部重送一次**：

```
系統指令 ＋ 工具定義（含 MCP schema）＋ 記憶／Project 指令
＋ 完整對話歷史 ＋ 歷次工具結果 ＋ 這次的新輸入
```

有兩個細節最常被忽略：

1. **每次工具呼叫也算一輪。** Claude 讀一個檔案、搜尋一次網頁、呼叫一次 Figma，都是「念完整本 → 做一個動作 → 拿到結果 → 再念一次整本」。你只問了一句，背後可能跑了十五輪。
2. **工具結果會永久留在記錄裡。** 讀過的檔案、搜到的網頁、跑過的測試輸出，從此之後每一輪都要再念一次。

![[token-01-context-stack.svg]]

### 為什麼是「越聊越貴」，而不只是「聊越多越貴」

把它寫成算式：

- 固定前綴 **F**：系統指令、工具定義、記憶這些每輪都有的東西
- 每輪新增 **k**：你的問題＋Claude 的回答＋工具結果
- 第 n 輪要念的量 ≈ F ＋ n × k
- **N 輪加總 ≈ N·F ＋ k·N²/2**

那個 **N²** 就是關鍵。舉個簡化的例子，假設 F = 1 萬 tokens、k = 2 千 tokens：

| 對話長度 | 固定前綴的部分 | 歷史累積的部分 | 合計 |
|---|---|---|---|
| 20 輪 | 20 萬 | 40 萬 | 60 萬 |
| 40 輪 | 40 萬 | **160 萬** | 200 萬 |

對話長度只加倍，歷史累積的部分卻變成 **4 倍**，總量變成 3.3 倍。這就是為什麼「一直在同一個對話裡聊」是最常見的額度殺手。

> [!example] 參考量級
> Claude Code 還沒開始工作，光是系統提示、工具 schema、MCP、CLAUDE.md 就可能有數萬 tokens 的固定開銷；讀一個 500 行的檔案大約 5–8K tokens。F 本身就不小。

## 原理二：不同的字，價格不同

回到顧問。助理念的頁面，其實有幾種不同的念法：

- **念「已經翻好、貼了便利貼」的頁面**：很快，幾乎不費力 → 這是**快取讀取**
- **念新的頁面，順便貼上便利貼**：比平常慢一點 → 這是**快取寫入**
- **念沒貼便利貼的新頁面** → 一般輸入
- **顧問親手寫回答**：最慢、最貴 → 這是**輸出**

![[token-01-weights.svg]]

| 類型 | 權重（一般輸入 = 1） | 什麼時候發生 |
|---|---|---|
| 快取讀取 | **0.1** | 前綴沒變、還在快取期限內 |
| 快取寫入（5 分鐘 TTL） | **1.25** | 第一次送出，或快取過期後重寫 |
| 快取寫入（1 小時 TTL） | **2** | API 可選的長效快取 |
| 一般輸入 | 1 | 沒進快取的新內容 |
| 輸出 | **約 5** | 模型產生的每一個字 |

兩個直接的推論：

- **快取命中可以省 90%**：同樣 10 萬 tokens 的歷史，命中快取只算 1 萬。
- **輸出是最貴的動作**：請 Claude 把一份 3,000 tokens 的文件「整份重寫」，相當於 15,000 單位的輸入。只要它改一段，成本就降到零頭。

## 原理三：便利貼五分鐘就會被撕掉

快取很好用，但有兩個陷阱。

### 陷阱一：前面一改，後面全部重來

快取是**從第一頁開始比對**的。只要前面的內容有任何變動，例如換了 Project 指令、中途開關 MCP、換模型，從變動那一頁之後的便利貼全部失效，整本重新以 1.25 的價格寫入。

### 陷阱二：停太久就過期

預設的快取只保留 **5 分鐘**。

想像你跟 Claude 聊了一個早上，歷史累積到 10 萬 tokens。這時你起身去倒杯咖啡、順便跟同事聊了兩句，回來時已經過了 8 分鐘。你打下一句「好，繼續」：

- 如果快取還在：10 萬 × 0.1 ＝ **1 萬**
- 快取過期了：10 萬 × 1.25 ＝ **12.5 萬**

**同一句話，貴了 12.5 倍。**

![[token-01-cache-ttl.svg]]

> [!warning] 最貴的組合
> **長對話 ＋ 常常中斷** ＝ 每次回來都用最高價重念整本。這是很多人「明明沒做什麼，額度卻掉很快」的原因。

## 原理四：額度有兩道閘門

以訂閱方案來說，額度有幾個特性要先知道：

- **一個池子大家共用**：claude.ai 網頁、桌面版、Claude Code、雲端 session、subagent 都從同一個池子扣。
- **兩道限制同時存在**：
  - **5 小時滾動時段**：從你這個時段的第一則訊息開始算
  - **每週上限**：獨立計算，5 小時重置**不會**補回每週額度
- **`/clear` 開新對話不會重置額度**，它只是讓接下來每一輪變便宜。
- **想知道錢花在哪**：Claude Code 裡的 `/usage` 會列出用量，訂閱方案還能看到 skills、subagents、plugins、各 MCP server 的占比。

第 06 篇會專門講怎麼利用「5 小時從第一則訊息開始算」這個特性。

## 原理五：記憶與 Project 是怎麼被塞進去的

回到助理的那本記錄，「公司簡介」和「顧問守則」那幾頁是怎麼來的？

| 來源 | 注入方式 | 對用量的意義 |
|---|---|---|
| 偏好設定（preferences）、個人檔案（profile） | **每輪全文注入** | 寫越長，每一輪都多付一次 |
| 其他記憶檔 | 只放索引，需要時才讀 | 讀了就進 context，之後每輪都在 |
| Project 指令 | 每輪注入 | 穩定不變 → 快取友善 |
| Project 文件 | 小的直接放入，大的走檢索 | 檢索到的片段進 context |
| 過去對話搜尋 | 每次呼叫帶回片段 | 跟搜尋結果一樣是工具結果 |

結論是：**常駐的東西要短，穩定的東西放前面，用不到的東西不要掛著。**

## 帶走這四個槓桿

整個系列的所有技巧，都在操作下面四個槓桿之一：

| 槓桿 | 對應原理 | 典型做法 |
|---|---|---|
| **讓 context 變小** | 一、五 | 精簡 CLAUDE.md、關掉用不到的 MCP、雜訊工作交給 subagent |
| **讓輪數變少** | 一 | 指名檔案、意見集中一則、A/B/C 並排比較 |
| **讓輸出變短** | 二 | 先要大綱、只回傳修改段落、可調參數集中 CONFIG |
| **讓快取持續命中** | 三 | 不在中途改前綴、要離開就先寫交接摘要、回來開新對話 |

> [!tip] 一句話記住
> 顧問沒有記憶，所以**你給他看的每一頁，都要一直付錢。** 少給、給對、讓他少寫。
