## 我的競品分析翻車記

這次的主角是我自己。

老闆要一份競品分析，下週一要給。我開了一個對話，請 Claude 幫我研究五家競品的定價與功能。結果不錯，但總覺得不夠深。於是：

> 「A 公司的企業方案再查深一點。」
> 「B 公司最近有沒有新發表？」
> 「幫我抓 C 公司的定價頁面全文。」
> ……

七輪之後，資料看起來很完整了。我接著在**同一個對話**裡說：「好，根據以上，寫一份競品分析報告。」

Claude 寫出了一份四千字的報告。我改了幾個地方，請它「重新整理一版」。再改，再「重新整理一版」。

寫到第三版時發生兩件事：第一，額度快見底了；第二，Claude 開始把 A 公司早期查到的舊價格，跟後來查到的新價格混在一起。

## 行李箱越塞越滿

回頭看那個對話，裡面躺著：

- 七次搜尋，每次約帶回 10 筆結果的文字
- 四次整頁抓取，每一頁都是完整網頁內容
- 三版四千字的完整報告

**搜尋結果就像出差時塞進行李箱的資料。** 你真正需要的只是最後的結論，但只要還在同一個對話裡，你每走一步都得拖著整個箱子，而且箱子只會越來越重。

更麻煩的是，箱子裡新舊資料混在一起，Claude 也會翻錯。

> [!info] 為什麼搜尋特別重
> - 搜尋結果和網頁抓取都是體積很大的「工具結果」，進了歷史就每輪重送
> - extended（深度）搜尋單次成本是 standard 的數倍
> - 在同一個長對話裡反覆「再查深一點」，歷史只會越疊越厚

## 研究階段：先講清楚要什麼

### 開場就把範圍說清楚

```text
研究 A、B、C 三家的企業方案定價（2026 年現行版本）。
standard 搜尋即可，每家 2–3 個來源，以官網為優先。
最後用表格整理，附 Sources。
```

範圍、來源數量、搜尋深度，一開始就說好，Claude 就不會自己無限延伸。

### 廣度和深度是兩回事

| 你需要的 | 適合的做法 |
|---|---|
| 多方交叉比對、避免單一來源偏誤 | **廣度**：多個 standard 搜尋 |
| 冷門資訊、很新的消息、需要挖很深的單一問題 | **extended** 搜尋 |

多數商業研究需要的其實是廣度，而不是 extended。

### 學會看 Sources

- **有附來源**：這一點是查證過的
- **沒附來源**：這一點來自模型本身的訓練知識

只需要針對「沒附來源、而且很重要」的那幾點追查，不必每一點都「再查深一點」。

### 概念題不用搜

「什麼是 FinOps？」「SaaS 和 PaaS 的定價邏輯差在哪？」這類不需要即時資料的問題，直接說「不用搜尋」，可以省下一整輪的搜尋結果。

## 關鍵一招：研究與產出分家

![[token-04-research-split.svg]]

**對話一：研究。** 最後一步請 Claude 產出一份「研究摘要」：

```text
研究到這裡。請整理一份研究摘要：
1. 每家的結論（表格）
2. 仍不確定、需要人工確認的點
3. Sources 清單
只要結論，不要過程。
```

**對話二：寫作。** 開一個新對話，貼上那份摘要，再開始寫報告。

整箱行李換成一張清單。寫作對話從一份乾淨、小巧、而且已經去除新舊衝突的資料開始，每一輪都便宜，Claude 也不會再翻錯。

> [!tip] 這等於手動 compact
> 研究摘要就是用「結論」取代「原始資料」。資訊有損失，但損失的大多是你本來就不需要的過程。

## 寫作階段：讓 Claude 少寫一點

輸出的權重約是輸入的 5 倍。寫作階段省額度的核心只有一件事：**不要讓它整份重寫。**

### 先要大綱

```text
先給我大綱：章節標題，每節一句話說明重點。確認後再展開。
```

大綱可能只有兩百字。方向錯了，改大綱的成本遠低於改四千字的全文。

### 修改時只要那一段

```text
只改第 3 節「定價比較」，其他不動。只回傳修改後的第 3 節。
```

或者更精確：

```text
用 diff 格式告訴我要改哪幾句。
```

### 小改自己動手

如果文件是 Claude 的 Docs 或 Sheets 類 artifact，可以直接在裡面編輯。改一個數字、調一個用詞，自己動手比請 Claude 重出一版快，也不花額度。

### 指定長度與格式

「每節不超過 150 字」「用表格」「三個重點 bullet」：明確的限制直接減少輸出量。

### 範本放在固定的地方

報告範本、寫作風格、公司用語規範，放進 Project 文件或做成 skill，不要每次重貼。Project 指令是穩定的前綴，對快取也友善。

## 改完之後

第二次做競品分析：一個對話專心研究（standard 搜尋、每家三個來源）→ 產出研究摘要 → 新對話貼摘要 → 先要大綱、確認 → 展開 → 只針對兩節要求修改段落 → 最後幾個用詞自己在文件裡改掉。

報告品質更好，因為寫作時 Claude 只看到乾淨的結論；用量大約是第一次的三分之一。

## 速查表：技巧與原理

| 技巧 | 對應原理 |
|---|---|
| 開場講清範圍與來源數 | 減少搜尋輪數與工具結果 |
| 廣度優先，extended 用在刀口 | extended 單次成本高 |
| 研究與產出分家 | 摘要取代原始結果，歷史變小 |
| 先大綱 | 輸出最貴，先用小輸出確認方向 |
| 只回傳修改段落、給 diff | 輸出量從整份降到一段 |
| 小改自己動手 | 0 輪、0 輸出 |
| 範本放 Project／skill | 穩定前綴、快取友善 |

> [!tip] 一句話記住
> **研究完只帶結論走；寫作時只叫它改那一段。**
