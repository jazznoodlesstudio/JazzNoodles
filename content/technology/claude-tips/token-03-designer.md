## 小米的十四輪

小米是團隊裡的 UI 設計師。新活動的 landing page 在 Figma 裡已經完成，她想請 Claude 直接轉成網頁原型，給工程師參考。

她把整個頁面的 Figma 連結貼給 Claude，Claude 透過 Figma MCP 抓回整頁的結構，產出一份完整的 HTML。很漂亮，八成像了。

接下來是這樣的：

> 第 1 輪：「主按鈕再大一點。」（附截圖）
> 第 2 輪：「顏色再淡一點。」（附截圖）
> 第 3 輪：「太淡了，淡回來一點。」（附截圖）
> 第 4 輪：「標題字距收一點。」（附截圖）
> ……
> 第 14 輪：「卡片圓角改回 12。」（附截圖）

每一輪，Claude 都重新輸出整頁 HTML。第十四輪送出後，額度到了。

小米說：「我又沒叫它做什麼大事，每次只改一個數字而已。」

## 三重成本疊在一起

小米每次確實只想改一個數字，但每一輪實際付出的是：

> [!failure] 成本一：MCP 回傳的整頁結構
> 對整頁或大 frame 呼叫 `get_design_context`，回傳的是大量結構與程式碼。這份工具結果進了歷史，之後每一輪都要重送。

> [!failure] 成本二：每張截圖都在累積
> 一張截圖大約一千個 tokens 起跳，而且**之後每一輪都會重送**。第十四輪時，前面十三張截圖還全部都在。

> [!failure] 成本三：整頁重寫是大量輸出
> 改一個色碼，Claude 卻輸出整頁 HTML。輸出的權重約是輸入的 5 倍，這是最貴的動作。

再加上 [[token-01-amnesiac-consultant|第一篇]]講的 N² 成長：第十四輪不只是第一輪的價格，而是要背著前面十三輪的所有截圖、所有整頁 HTML 一起送出。

---

## 解法：讓「調整」不需要回來問 Claude

設計微調的本質是**試錯**，試錯本來就需要很多次。問題不在次數，而在每一次都要經過 Claude。所以解法的方向是：**把試錯的迴圈從 Claude 身上移開。**

![[token-03-rounds.svg]]

### 解法一：CONFIG 區

請 Claude 一開始就把所有可調參數集中在檔案頂端：

```js
const CONFIG = {
  primaryColor: '#3B6FE0',
  buttonSize: 'lg',        // sm | md | lg
  headingLetterSpacing: '-0.01em',
  cardRadius: 12,
  heroImageOpacity: 0.85,
};
```

之後要改按鈕顏色，小米自己改一行就好。**零輪、零輸出。**

可以這樣開場：

```text
把這個設計轉成 HTML。所有顏色、尺寸、間距、圓角都放在
檔案最上方的 CONFIG 物件裡，頁面內容只引用 CONFIG。
```

### 解法二：頁面內調整面板

不想碰程式碼？請 Claude 在頁面角落加一個調整面板：

```text
在右下角加一個可收合的調整面板：主色用色票、按鈕大小
用下拉選單、圓角和透明度用 slider，即時預覽，
並有一個按鈕可以把目前的數值複製成 CONFIG。
```

小米可以自己拉 slider 拉到滿意，再把最終數值一次貼回去。原本十四輪的試錯，全部在瀏覽器裡完成。

### 解法三：A/B/C 並排

拿不定方向的時候，不要一個一個試：

```text
主視覺區給我三個方向並排：A 保守（接近現有品牌）、
B 大膽（高對比）、C 留白多。其他區塊不用動。
```

一輪看到三個選項，取代三輪的來回，而且比較時更容易做決定。

### 解法四：意見集中成一則

看完整頁之後，一次列出所有修改：

```text
請一次修改以下 5 點，只回傳修改的部分：
1. 主按鈕改 lg
2. 標題字距 -0.02em
3. 卡片圓角 12
4. Footer 背景改 #F5F6F8
5. 手機版 hero 圖改成置中
```

一則五點 ＝ 1 輪；分五則傳 ＝ 5 輪，而且每一輪都比上一輪更貴。

## 跟 Figma MCP 相處的方式

**先小後大。** 不要一開始就對整頁呼叫 `get_design_context`：

1. 先用 `get_metadata` 看整體結構，知道有哪些 frame 和 node
2. 再針對**單一 node 或 frame** 呼叫 `get_design_context`
3. 一個區塊做完，再做下一個

**截圖要精準。** 只截需要的區塊；同一個主題不要重複貼好幾張相似的截圖，前一張已經在歷史裡了。

**視覺定調提前。** 配色、字體、間距系統這些「全域決策」越早確定越好。定調之後，開一個新對話，把確定的設計規範用一段交接摘要帶過去（做法見 [[token-05-checkpoints|第五篇]]），前面所有的試錯截圖就不用再背著走。

---

## 改完之後

小米的第二個專案：`get_metadata` 看結構 → 只抓 hero 區塊 → 產出時帶 CONFIG 與調整面板 → 自己在瀏覽器裡調了二十幾次 → 把最終 CONFIG 貼回，加上一則集中意見 → 定調後開新對話做下一個區塊。

同樣的頁面，跟 Claude 的來回從十四輪變成四輪。

## 速查表：技巧與原理

| 技巧 | 對應原理 |
|---|---|
| CONFIG 區、調整面板 | 試錯迴圈離開 Claude：0 輪、0 輸出 |
| 意見集中一則 | 5 輪變 1 輪，避開 N² 成長 |
| A/B/C 並排 | 一輪取代三輪 |
| `get_metadata` → 單一 node | 工具結果變小，每輪重送的量變小 |
| 精準截圖、不重複貼 | 圖片 tokens 每輪重送 |
| 只回傳修改部分 | 輸出權重約 5，局部修改最划算 |
| 定調後開新對話 | 丟掉試錯歷史，歸零 N |

> [!tip] 一句話記住
> **讓 Claude 做一個「可以自己調」的東西，而不是每次都請它幫你調。**
