## 兩百則訊息的對話

阿哲是團隊的資深工程師，這次要用 Claude 做一個內部報表工具的原型。

第一天，他們討論需求、定了配色、搭好骨架。第二天，加功能、修 bug、改版面。第三天，繼續加功能。全部在**同一個對話**裡完成，因為「這樣 Claude 才記得前面的脈絡」。

第三天下午，奇怪的事情開始發生：

- Claude 把第一天決定棄用的藍色主題又加了回來
- 它引用了一個第二天早上已經刪掉的函式
- 每送出一則訊息，額度條就明顯掉一截

阿哲以為對話越長，Claude 記得越多。實際上剛好相反。

## 長對話的三個問題

> [!failure] 問題一：N² 成長
> 第二百輪要重送前面一百九十九輪的全部內容。對話長度加倍，歷史累積的成本約變成 4 倍（原理見 [[token-01-amnesiac-consultant|第一篇]]）。

> [!failure] 問題二：中斷就過期
> 三天裡，阿哲每天都會離開好幾次：開會、吃飯、下班。每次回來，整段越來越長的歷史都以 1.25 的價格重寫，而不是 0.1 的價格讀取。

> [!failure] 問題三：失敗的分支也在付費
> 被否決的藍色主題、刪掉的函式、改錯又改回來的版本，全都還在歷史裡。它們不只花錢，還會**誤導 Claude**：新舊決策混在一起，它分不清哪個才是現在的。

長對話不是「記得更多」，而是「背著更多過期的東西，而且分不清哪些過期了」。

---

## 解法：檢查點制

把長任務切成幾個階段，每過一個檢查點（Checkpoint, CP）就**開一個新對話**，用一份交接摘要延續。

![[token-05-checkpoints.svg]]

| 檢查點 | 要確認的事 | 產出 |
|---|---|---|
| **CP0 方向** | 要解決什麼問題、給誰用、不做什麼 | 一段目標與範圍說明 |
| **CP1 骨架** | 頁面結構、資料流、技術選擇 | 可以跑的最小版本 |
| **CP2 視覺定調** | 配色、字體、間距、元件風格 | 設計規範（**這一步要提前**） |
| **CP3 功能** | 一次加一組功能，不要一次全部 | 每組功能各自一段 |
| **CP4 打磨** | 邊界情況、錯誤處理、細節 | 可以給別人試用的版本 |
| **CP5 發布** | 部署、文件、交接 | 正式版本 |

> [!tip] 為什麼視覺定調要提前
> 視覺是最容易反覆試錯的部分。如果放到最後，所有試錯都會堆在一個已經很長的對話裡；放在 CP2，定調完就開新對話，試錯的歷史直接丟掉。

### 交接摘要怎麼寫

每到一個檢查點，請 Claude 寫一份交接摘要：

```text
我們完成了 CP2。請寫一份交接摘要，讓一個全新的對話
能直接接手。包含：
1. 已確認的結論（只寫最終決定，不寫討論過程）
2. 明確放棄的方向（一句話說明原因）
3. 目前的檔案結構與關鍵檔案
4. 下一步（CP3 要做的第一組功能）
控制在 300 字以內。
```

然後開新對話，第一句貼上這份摘要。

注意第 2 點：「明確放棄的方向」寫成一句話就好。這樣新對話知道藍色主題已經被否決，但不需要背著當初討論藍色主題的二十則訊息。

### 不變的規則放 Project 指令

技術選擇、命名規範、設計規範這些整個專案都不會變的東西，放進 Project 指令，不要每次都寫進交接摘要。Project 指令是穩定的前綴，每個新對話都自動帶著，對快取也最友善。

## 另外三個小習慣

### 錯了就編輯，不要追加

Claude 理解錯了，最直覺的反應是再發一則：「不對，我的意思是……」

但這樣錯誤的那一輪就永遠留在歷史裡了。更好的做法是**回去編輯你上一則訊息**，把它改成正確的說法再送出。錯誤的分支會從 context 中移除，就像沒發生過一樣。

```
追加：  問題 → 錯誤回答 → 「不對」 → 正確回答     （4 段都留在歷史）
編輯：  問題（改過）→ 正確回答                     （只留 2 段）
```

### 不要反覆貼整份文件

文件已經在對話裡了，就不要再貼一次。要討論某一部分，就說「只看第 3 節」，或者只貼那一段。

### 要離開很久，先寫摘要

知道自己要離開超過五分鐘（開會、午餐、下班），就先請 Claude 寫一份交接摘要。回來的時候開新對話、貼摘要，而不是對著一個快取早已過期的長對話說「繼續」。

## 改完之後

阿哲的下一個原型：CP0 用一個短對話釐清範圍 → CP1 骨架 → CP2 提前定調，試了五套配色，定案後開新對話 → CP3 分三組功能，每組一個對話 → CP4、CP5。

總共七個對話，每個都不超過四十則訊息。Claude 再也沒有把棄用的主題加回來，因為新對話裡根本沒有那段討論，只有一句「已放棄藍色主題（對比不足）」。

## 速查表：技巧與原理

| 技巧 | 對應原理 |
|---|---|
| 每過一個 CP 開新對話 | 歸零 N，打斷 N² 成長 |
| 交接摘要 | 用有損但極小的歷史取代完整歷史 |
| 「明確放棄的方向」寫一句 | 保留決策、丟掉討論過程 |
| 規則放 Project 指令 | 穩定前綴，快取友善 |
| 編輯訊息取代追加 | 從 context 移除失敗分支 |
| 離開前寫摘要 | 避開快取過期後的 1.25 重寫 |

> [!tip] 一句話記住
> **長任務要切段走；每一段只帶著結論出發，不帶著過程。**
