## 錯題回溯：不要只記答案

每答錯一題，填這四欄：

| 欄位 | 內容 |
|---|---|
| 這題考哪個目標／哪一篇 | 例如 #23，05 篇 |
| 我選了什麼、為什麼覺得對 | 找出自己的推理漏洞 |
| 正解的關鍵判斷是什麼 | 一句話，例如「強制呼叫才有格式保證」 |
| 干擾選項長什麼樣 | 例如「在提示加強語氣」屬於建議層 |

這幾個錯誤選項在整個系列中不斷重複出現，熟悉它們比背答案有用：

| 常見錯誤選項 | 為什麼錯 | 出處 |
|---|---|---|
| 在 CLAUDE.md、system prompt 加強語氣 | 建議層沒有保證 | 03 |
| 用模型輸出的文字判斷結束 | 該看 `stop_reason` | 01 |
| 把整個資料夾讀進 context | 該先 Grep／Glob 縮小範圍 | 04 |
| 所有欄位必填 | 逼模型編造 | 05 |
| 回傳一句 `"error"` | 錯誤沒有分類 | 06 |
| 用情緒或自評信心決定升級 | 不可靠的替代指標 | 07 |

## 答題策略

- **先找「後果」**：題目描述了什麼出了事？有金錢、合規、資料後果的，答案通常在強制層（程式、hook、schema）。
- **排除「更用力地請求」**：選項若只是「加強提示」「再提醒一次」，先打叉。
- **排除「過度工程」**：小問題的解法若是大改架構，多半不是正解。
- **找出「原因」而非「症狀」**：選項若處理的是症狀（事後補救），而另一個處理根因，選根因。
- **看情境的關鍵詞**：「不確定有幾個」→ 動態拆解；「使用者在等」→ 同步；「全組共用」→ project 範圍；「不能被違反」→ 強制層。
- **遇到不確定的題先標記，往下做**：時間平均約每題 2 分鐘，卡住就跳過，最後回頭。

> [!note] 這些是判斷習慣，不是考題解法
> 我沒有看過真實題目，也不會寫它們。這些是從官方考試目標與各主題的設計原則歸納出來的思考方向。

## 考試當天檢查清單

**前一天**
- [ ] 確認考試時間、時區、需要的證件與設備
- [ ] 測試網路、攝影機、麥克風（若為遠端監考）
- [ ] 清理桌面，準備符合規定的環境
- [ ] 不要熬夜複習新內容，只翻速查表

**當天**
- [ ] 提早進場，預留系統檢查時間
- [ ] 準備好水與必要的休息安排（依監考規則）
- [ ] 開始前深呼吸，提醒自己：這張考卷在考判斷

**作答中**
- [ ] 先看情境，再看問題，再看選項
- [ ] 卡住就標記、跳過
- [ ] 最後 15 分鐘回頭檢查標記的題目
- [ ] 不要因為某個選項「看起來很專業」而選它，回到「後果」與「誰來保證」

## 速查：整個系列一頁版

| 篇 | 一句話 |
|---|---|
| 01 | 看 `stop_reason`，不聽模型說了什麼；每個 session 都要有收尾 |
| 02 | 動態拆解、結構化交接、續接前先確認世界變了沒、用 subagent 隔離 context |
| 03 | 「出事會痛」的規則交給程式，「做得更好」的規則交給模型 |
| 04 | 先 Grep 再 Read，越難回頭越要 plan，要共用的東西放進版控 |
| 05 | 格式靠 schema 約束，內容靠驗證把關，不趕的交給 Batches |
| 06 | 描述寫清楚、錯誤分類、順序由程式保證 |
| 07 | 升級用看得見的條件，信心要校準，修正要回饋 |

> [!tip] 一句話
> 考試會不斷問同一件事：這件事該由誰負責保證？
