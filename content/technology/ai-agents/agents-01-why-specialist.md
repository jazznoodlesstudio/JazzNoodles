# 為什麼要把 SDLC 拆成專職 agent

> [!abstract] 這篇的重點
> 一個 agent 從頭做到尾，問題不在它不夠聰明，而在**沒有人能檢查它**。拆成專職 agent，加上「只讀自己的輸入、只寫自己的輸出」的規則，才有可以被驗收的接力點。

## 一個週五下午

那天下午，我把需求丟給 AI：「從 PRD 一路做到使用者手冊，一次做完。」

四十分鐘後，一整疊文件和程式碼躺在資料夾裡。看起來很完整。

小安翻到 API 設計，皺了眉：「這個欄位在 PRD 叫 `export_range`，到 SD 變成 `date_range`，程式碼裡又是 `range`。」

我問 AI 為什麼不一致。它很誠懇地回答：「寫到後面我調整了想法。」

我沒辦法生氣。它確實調整了，只是沒有任何人、任何機制知道它調整了。

## 問題漏在哪

單一 agent 一口氣做完整條流程，通常漏在三個地方：

> [!failure] 漏洞一：自己審自己
> 寫 PRD 的和寫 QA 測試計畫的是同一段上下文，它會**順著程式碼寫測試**，而不是照著需求驗收。測試永遠會過，因為考卷是照答案出的。

> [!failure] 漏洞二：沒有停下來的地方
> 一口氣做完，就沒有「這份文件人看過了」的時刻。等你發現方向錯了，後面五份產物都蓋在上面。

> [!failure] 漏洞三：改一處，不知道動到哪裡
> 它「調整了想法」的時候，沒有紀錄、沒有指紋。下游文件和程式碼各自活在不同版本裡。（這一點下一篇會專門處理。）

## 解法：每個人只跑自己那一棒

我的做法是把流程切成專職 agent，每個只做一件事。目前實作的是十二個：

| 階段 | Agent | 產出 |
|---|---|---|
| 選用 | 市場調查、需求訪談 | MARKET-SURVEY、INTAKE |
| 文件 | PRD、SA、SD | PRD.md、SA.md、SD.md |
| 開發 | 開發、Code Review | `src/`、審查報告 |
| 驗證 | QA、自動化測試 | 測試計畫與報告、`tests/` |
| 收尾 | 使用者手冊 | USER-MANUAL.md |
| 循環 | Bug 回報、Bug 修復 | 工單、修復 commit |

拆開之後，靠三條約定讓它真的能運作：

**約定一：只讀自己宣告的輸入、只寫自己負責的輸出。**

```markdown
---
name: sa-agent
description: 依 PRD 產出/更新 SA 文件。只讀 artifacts/PRD.md，只寫 artifacts/SA.md。
tools: Read, Write, Edit, Grep, Glob
---
你是系統分析師。輸入是 artifacts/PRD.md（以及變更時的 PRD diff）。
產出 artifacts/SA.md，每個 use case 必須標注對應的 PRD 條目編號。
```

`tools` 只給它需要的，它連別人的產物都碰不到。

**約定二：每個 agent 有可驗收的標準。** 例如 SA 的 use case、資料流、外部介面，都必須能追溯到 PRD 條目；沒有對應條目的內容，驗收不通過。

**約定三：QA 以 PRD 為準，不以程式碼為準。** 這一條專門對付「自己審自己」。QA agent 的輸入是 PRD 和 SA，程式碼只用來執行，不用來決定測什麼。

另外兩條界線一起說清楚：agent 之間**不直接對話**，只透過產物檔案；一個 workspace 只跑一條流水線，不做專案排程、估時、人力。

## 改完之後

同一個週五下午，同一個需求。

這次 PRD agent 先交出 `PRD.md`，流程停下，我簽名核准。SA agent 只讀得到這份 PRD，use case 旁邊都標著 PRD 條目編號。到 SD 的時候，`export_range` 這個名字已經被前面的文件固定住，後面想改，要走「上游變更」的流程，而不是悄悄換掉。

小安翻開文件的時候沒有皺眉，他問的是：「FR-03 的驗收條件可以再具體一點嗎？」

這才是我想要的對話：討論需求，不是抓不一致。

## 速查表

| 做法 | 對應的原理 |
|---|---|
| 一人一棒（專職 agent） | 縮小每段的責任，才有地方驗收 |
| 只讀宣告的輸入 | 避免上下文污染，也讓依賴關係看得見 |
| `tools` 只給必要的 | 權限最小化，agent 越界時直接做不到 |
| QA 以 PRD 為準 | 考卷不能照答案出 |
| 文件階段逐份核准 | 在錯誤擴散前插入人的判斷 |

> [!tip] 一句話記住
> ==拆成專職 agent 的目的，不是讓它們各自更聰明，而是讓每一段產出都有人可以檢查。==
